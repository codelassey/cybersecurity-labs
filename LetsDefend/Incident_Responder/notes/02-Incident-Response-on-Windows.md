# Incident Response on Windows - Summary Notes

## Incident Response Lifecycle (6 Stages)

### 1. Preparation
- Central log collection system
- NTP time synchronization across all devices
- Consistent user account naming conventions
- Document system/service administrators
- Asset management with patch versions
- Secure out-of-band communication methods
- Legal procedures documented in advance

### 2. Identification
- Gather preliminary information
- Assign primary investigator
- Use standardized checklists
- Determine if event is suspicious or false positive

### 3. Scope
- Characterize event type (DDoS, malware, data leak, etc.)
- Take immediate containment actions (account disable, IP block)
- Collect volatile memory, firewall logs, network traffic
- Isolate compromised systems (not just unplug)

### 4. Eradication
- Identify root cause
- Clean disk if rootkit suspected, restore from clean backup
- Apply latest updates after restoration
- Improve defenses based on findings
- Run vulnerability scans

### 5. Recovery
- Verify logging, systems, applications work correctly
- Coordinate restoration process
- Monitor for recurring events

### 6. Lessons Learned
- Document findings for both technical and executive audiences
- Identify what worked well and what failed
- Provide recommendations for improvement

---

## Incident Response Procedure (SOC Workflow)

**Alert** → **Analyze** → **Investigate** → **Assess Impact** → **Contain** → **Respond**

- **Alert:** Generated by SIEM from EDR, IDS, IPS, WAF logs
- **Analyze:** Tier 1 analyst determines false positive or real threat
- **Investigate:** Source of attack, attacker progress, timeline
- **Assess Impact:** Affected systems, damage assessment
- **Contain:** Isolate affected devices from network
- **Respond:** Remove threats, restore systems, apply lessons

---

## 3 Critical Questions for Any Investigation

1. Is there malware actively running in the system?
2. Is there suspicious internal or external communication?
3. Is there persistence established?

## Live Memory Analysis with Process Hacker

### 3 Critical Areas to Examine

**Process Tree**
- Normal: chrome.exe creates child chrome.exe processes (tabs)
- Suspicious: powershell.exe or cmd.exe under chrome.exe, winword.exe, or web server processes
- Example 1: PowerShell under web server process running whoami/net user = probable webshell
- Example 2: PowerShell under Winword.exe with base64 encoded command = malicious macro

**Network Connections**
- Check Network tab in Process Hacker
- Look for unexpected processes communicating externally
- Verify remote IP addresses against threat intelligence (VirusTotal, AbuseIPDB)
- Check for unusual ports

**Signature Status**
- Enable "Verification Status" and "Verified Signer" columns
- Signed files are generally more trustworthy but can still be malicious (SolarWinds example)
- Start with unsigned files for investigation

## User Account Analysis

### Current User Detection
```
net user
net user USERNAME
```


- Use lusrmgr.msc for GUI view
- Watch for generic names: support, sysadmin, admin

### Historical User Creation
**Event ID 4720:** A user account was created
- Check creation time against attack timeline
- Identify which user created the suspicious account

### Privilege Escalation Detection
**Event ID 4732:** A member was added to a security-enabled local group
- Check for unexpected additions to Administrators group

## Scheduled Tasks

### Detection Tools
- Autoruns (Sysinternals) → Scheduled Task tab
- Task Scheduler (built-in)
- Command: `schtasks`

### Suspicious Task Indicators
- Missing Publisher information
- Suspicious Image Path
- Generic task names (Update, Cleanup, etc.)

### Historical Detection
**Event IDs:**
- **4698:** A scheduled task was created
- **4702:** A scheduled task was updated

### Log Location
Applications and Services Logs → Microsoft → Windows → TaskScheduler → Operational.evtx

---

## Services

- Attackers create new services or modify existing ones
- May use legitimate-looking names (Chrome Update)
- May disable security services (Windows Defender, Firewall)

### Detection
**Event ID 4697:** A service was installed in the system

## Registry Run Keys / Startup Folder

### Registry Keys to Check
```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunOnce
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\RunOnce
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\UserShellFolders
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\ShellFolders
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\ShellFolders
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\UserShellFolders
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\RunServicesOnce
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\RunServices
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\RunServices
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\Run
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer\Run
```


### Startup Folder Locations
```
C:\Users[Username]\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp
```



### Detection
- Autoruns tool → Logon and Explorer tabs
- Check Description and Publisher fields
- **Event ID 4657:** A registry value was modified

## File Analysis

### Manual Search
- Use Date Modified filter in File Explorer
- Focus on event timeframe
- Prioritize extensions: .bat, .exe, .ps1, .vbs

### Automated Search
- Run full AV/malware scanner
- Not 100% reliable against advanced threats

### Best Practice
Deploy EDR agents across all systems for centralized monitoring and detection

## Checklist for Windows Incident Response

### Memory Analysis
- [ ] Process Tree (suspicious parent-child relationships)
- [ ] Network Connections (unexpected processes, IPs, ports)
- [ ] Signature Status (unsigned files first)

### User Accounts
- [ ] Current users (net user / lusrmgr.msc)
- [ ] Historical user creation (Event ID 4720)
- [ ] Privilege escalation (Event ID 4732)

### Persistence Mechanisms
- [ ] Scheduled Tasks (Autoruns, Event IDs 4698, 4702)
- [ ] Services (Event ID 4697)
- [ ] Registry Run Keys (Autoruns, Event ID 4657)
- [ ] Startup Folder
- [ ] Suspicious files (manual + automated scan)

### Post-Incident
- [ ] Deploy EDR agents
- [ ] Centralized logging
- [ ] Document findings
- [ ] Update security controls

---

## Key Takeaways

- Always run analysis tools as Administrator
- Know what normal looks like before identifying abnormal
- Attackers use generic names to blend in
- Check both current state AND historical logs
- Persistence is the attacker's priority - check all persistence points
- Time synchronization is critical for correlating events
- Document everything for lessons learned
- The tool doesn't matter as much as knowing what to look for
